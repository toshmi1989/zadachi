# Задачи — контроль исполнения поручений

Платформа для ведения задач из выгрузки Excel (поручения по документам: Фармон, Қарор, ВМ, ПА, Баён):
кто отвечает, в какой срок, что выполнено. Главный экран — дашборд: у кого сколько задач, в каких сроках, в штуках и в процентах,
и любой элемент дашборда по клику открывает список именно этих задач.

## Роли

| | Администратор | Пользователь |
|---|---|---|
| Дашборд | да | да |
| Список задач | да, правка: ответственный, статус, дата закрытия (по одной и пачкой) | только просмотр; объём задаёт администратор в «Настройках»: все / только свои / ни одной |
| Пользователи, импорт Excel, настройки, копии | да | нет |

Права проверяются на сервере (`app/main.py`), а не только скрываются в интерфейсе.

## Как считаются сроки

В выгрузке два срока. **Официальный срок** («Топшириқ муддати») — из поручения. **Дата закрытия** («Ёпиш муддати») — внутренняя, её ставит и меняет администратор.
Просрочка и группы сроков считаются по выбранному на странице: по умолчанию по дате закрытия (если её нет — по официальному сроку).
Переключатель «Срок считать по» есть на дашборде и в списке; его выбор запоминается.

Группы (только для задач «Не выполнено» и «В работе»): просрочено · срок ≤ 7 дней · 8–30 дней · позже 30 дней · без срока.
«Выполнено» и «К сведению» в просрочку не попадают. Процент выполнения = выполнено / (все − к сведению).

## Импорт

Страница «Импорт» (администратор). Сначала проверка без записи: сколько новых, обновится, без изменений, какие сотрудники будут созданы, что не удалось прочитать.
Затем «Загрузить».

- Задача определяется по коду («Топшириқ коди»), поэтому повторная загрузка обновляет текст, документ и срок, а не дублирует.
- Всё, что администратор менял вручную (ответственный, статус, дата закрытия), повторной загрузкой не затирается.
- Сотрудники из колонки «Масъул ҳодим» создаются сами (роль «Пользователь», без пароля — войти нельзя, пока администратор не выдаст пароль на странице «Пользователи»).
- Нечитаемые даты (например, `16.17.2026`) не угадываются: поле остаётся пустым, строка попадает в список «Проверьте после загрузки». Опечатка `30.112026` понимается как 30.11.2026.
- Статусы из выгрузки: «Бажарилмаган» → Не выполнено, «Бажарилган» → Выполнено, «Маълумот учун қабул қилинган» → К сведению; пометки «Якунлаш», «Рақамлаштириш» сохраняются как метка.

Без браузера: `docker exec zadachi python -m app.cli import /data/файл.xlsx`.

## Запуск

```
cp .env.example .env     # впишите APP_PASSWORD (не короче 8 символов)
docker compose up -d --build
```

Первый вход: логин `admin`, пароль из `APP_PASSWORD` (без него пароль генерируется и один раз печатается в `docker logs zadachi`).
База — `/data/zadachi.db` (том `./data`). Копии каждые 6 часов в `/data/backups`, хранятся 14 последних; страница «Настройки» показывает последнюю и проверяет её.
Копируйте `/data/backups` на другую машину: на том же диске они не спасут от потери сервера.

На общей платформе: запись проекта уже есть в `platform/projects.json` репозитория murojat; `python3 manage.py deploy zadachi`.

Для разработки: `pip install -r requirements.txt pytest httpx && pytest`; `ZADACHI_TODAY=2026-11-16` фиксирует «сегодня».
Браузерная проверка: `BASE=http://localhost:8766 XLSX=файл.xlsx node tests/e2e/flow.js` (нужен Playwright).

## Устройство

FastAPI + SQLite (WAL), интерфейс на чистом JS без сборки (`app/static`), графики — SVG/CSS без библиотек.
Журнал изменений задач и журнал аудита защищены от правки и удаления триггерами БД.
Пароли — scrypt, заголовки безопасности и CSP, проверка Origin у запросов-записей, ограничение попыток входа.
Анимации отключаются при `prefers-reduced-motion`.
