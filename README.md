# Задачи — контроль исполнения поручений

Платформа для ведения задач из выгрузки Excel (поручения по документам: Фармон, Қарор, ВМ, ПА, Баён):
кто отвечает, в какой срок, что выполнено. Главный экран — дашборд из трёх таблиц по отделам (месяцы, виды документов, этапы согласования), в них выполнено / не выполнено
с процентами, и любое число по клику открывает список именно этих задач.

## Роли

| | Администратор | Сотрудник (пользователь) |
|---|---|---|
| Дашборд | да | да (общая картина по всем) |
| Список задач | все задачи; правка: ответственный, статус, дата закрытия (по одной и пачкой) | **только свои задачи**; статус своих задач меняет сам |
| Что сотрудник может менять | | только статус своей задачи: «Не выполнено», «В работе», «Выполнено». «К сведению», ответственного и дату закрытия ставит администратор |
| Пользователи, импорт, синхронизация, настройки, копии | да | нет |

Что говорит сайт ijro.uz по задаче (статус, ответы, ссылка) сотрудник видит у своих задач: в списке метка «на сайте: …», в карточке блок «С ijro.uz». Официальный срок и даты периодов ему при этом не показываются, а кнопки «Применить» нет: статусы с сайта применяет администратор.
Сотрудник видит и меняет только свои задачи, и это проверяется на сервере: чужая задача для него просто не существует (404), а лишние поля в запросе отклоняются (403). Каждое изменение пишется в историю задачи с именем того, кто его сделал; такая задача считается «правленной вручную», и повторный импорт Excel её статус не затирает. Администратор в «Настройках» может расширить видимость до «все задачи» (сотрудник их читает, но правит только свои) или оставить сотруднику только дашборд.
Если статус сотрудника расходится с сайтом ijro.uz (отметил «Выполнено», а на сайте не закрыто), администратору это видно при синхронизации (метка «у нас выполнена, на сайте нет»).

Права проверяются на сервере (`app/main.py`), а не только скрываются в интерфейсе.

**Официальный срок («Топшириқ муддати») видит только администратор.** Пользователь везде видит лишь дату закрытия: в списке, карточке, дашборде, Excel-выгрузке и напоминаниях в Telegram. Сервер не отдаёт ему официальную дату ни в каком виде и не подставляет её вместо пустой даты закрытия: у задачи без даты закрытия пользователь видит «срок не указан». Параметр `by=due` для него игнорируется. Поэтому у администратора и пользователя цифры на дашборде могут чуть различаться ровно на задачах, у которых нет даты закрытия.

## Синхронизация статусов с edo.ijro.uz

Официальный сайт открывается только по ЭЦП или OneID, поэтому платформа на него **не заходит сама**: статусы читает небольшой скрипт в браузере администратора (Tampermonkey), пока тот вошёл на ijro. Это полуавтоматический режим: вы входите на сайт и нажимаете «Синхронизировать».

1. «Синхронизация» → «Установить скрипт» (нужен Tampermonkey); создайте ключ и вставьте его в скрипте («⇄ Задачи» → «Ключ…»).
2. Войдите на edo.ijro.uz, откройте любой раздел «Топшириқлар» и нажмите «Синхронизировать». Скрипт берёт открытые задачи платформы, ищет каждую по коду в нужном разделе (Фармон, Қарор, Баён → документы Президента; ВМ → Вазирлар Маҳкамаси; ПА → Администрация Президента), читает статус и ответы («Берилган жавоблар») и отправляет их на платформу. Примерно 250 задач за пару минут, с паузами; при любой ошибке входа или лимите останавливается.
3. Платформа **ничего не меняет сама**: результат лежит как снимок, а экран «Что изменится» показывает расхождения. Применить можно выбранные или все «Выполнено»; изменение попадает в историю задачи.

Правила сопоставления статусов: 20 или 21 вместе с `is_done` → «Выполнено» (в срок или с опозданием); 2 → «В работе» (ответ дан, идёт согласование); 0 → «Не выполнено»; **неизвестные значения (1, 3, 4, −1) никогда не меняют статус**; «К сведению» не затирается; периодическая задача считается выполненной, только когда выполнены все периоды; задача, не найденная на сайте, отмечается и не меняется.

Ссылки: код задачи в списке и кнопка в карточке ведут на ijro.uz (в новой вкладке). Точная ссылка строится из адреса карточки, который задаётся в «Синхронизации» шаблоном с `{section_path}` и `{id}`; пока он не задан, ссылка ведёт в нужный раздел сайта. В карточке (только администратору) блок «С ijro.uz»: статус на сайте, дата проверки, цепочка ответов, кнопка «Применить».

Безопасность: ключ платформы показывается один раз, в базе только его хеш, отзывается в один клик, открывает лишь приём данных. Данные входа и сессия ijro не покидают браузер. Тексты ответов по задачам с пометкой «секретно» на платформу не копируются. Платформа принимает только коды, которые у неё уже есть, и не создаёт задач.
Скрипт и сервер проверяются на поддельном ijro (`tests/ijro/collector.test.js`, `seed.py`): MessagePack сверен байт в байт с эталонной библиотекой.
Если сайт изменит формат ответов, на странице ijro кнопка «Диагностика» выводит названия полей и их типы (без значений и текстов), чтобы быстро поправить скрипт.

## Импорт и синхронизация: база и этапы (скрипт 1.8.5)

Работа разделена на два действия:

1. **Загрузка базы задач** (страница «Импорт»). Каждая загрузка — это база: файлы Excel с сайта (можно выбрать сразу несколько, например по одному на раздел, они читаются вместе как одна база) **перезаписывают то, что есть на сервере**:
   - задачи из файла добавляются, у существующих обновляются тексты, документ, срок, **статус** и ответственный;
   - **ваши ручные правки перезаписываются** значениями из файла (перед загрузкой страница показывает, сколько). Дата закрытия, которой нет в файле, не стирается;
   - **задачи, которых нет в загруженных файлах, снимаются с дашборда, в том числе выполненные** (статус «Нет на сайте»; ничего не удаляется, при следующей загрузке они вернутся; добавленные вручную не трогаются), так что в базе остаётся только то, что в файлах;
   - **даты закрытия, которые были только предложены** (их никто не подтверждал), уходят вместе со старой базой: месяц задачи берётся по официальному сроку, пока специалист не поставит срок исполнения. Автоматический подбор дат закрытия по умолчанию выключен (галочка на странице «Импорт»); Если уходит больше четверти открытых задач (так бывает при неполной загрузке, например один раздел из трёх), загрузка требует явного подтверждения;
   - **какие строки берутся** — четыре независимых переключателя в «Настройки» → «Загрузка базы»: **только отделы нашей структуры** (включено по умолчанию: в таблице «Отделы в выгрузке» на странице «Импорт» вы сами решаете по каждому отделу файла, наш он или нет; «не наш отдел» = строки не загружаются), **только исполнитель «Соғлиқни сақлаш вазирлиги»**, **без соисполнителей и лишних видов документов** Кабинета, **только сроки в окне** (по умолчанию выключены: файлы вы отбираете сами). В предпросмотре видно, сколько строк отброшено и почему;
   - **отделы из файла, которых нет в структуре департамента**, видны на странице «Импорт» (блок «Отделы в выгрузке и соответствие нашей структуре»): у каждого отдела можно выбрать «наш: создать новый отдел из этого названия», а кнопка «Добавить в структуру» создаёт сразу все (их можно переименовать, перенести в управление или скрыть в «Настройках»), иначе их задачи лягут в строку «Без отдела»;
2. **Синхронизация** (кнопка «Синхронизировать» в скрипте на сайте ijro). Только читает с сайта историю этапов и записывает её к задачам, которые уже есть в базе. Новых задач не создаёт, статусы из базы не переписывает (статус «в работе» ставится сам, когда на сайте дан ответ: настройка автоприменения). По умолчанию проверяются **все невыполненные задачи базы** (база заменяется целиком при каждой загрузке и содержит только нужный период); отбор по месяцу — необязательная настройка, и скрипт после проверки пишет, сколько невыполненных задач осталось вне выбранного периода.

**«Палата вернула» и смена срока.** Когда Счётная палата приняла ответ к сведению («Маълумот учун қабул қилинди»), задача остаётся невыполненной и ждёт нашего ответа: этап «Палата вернула». Но если срок задачи на сайте был изменён ПОСЛЕ этого ответа, ждать от нас нечего: задача переходит в этап «Срок изменён после ответа Палаты» и на дашборде попадает в колонку «Другое»; новый срок по-прежнему записывается в платформу. Признаки (проверены по реальным карточкам сайта, разбор шести задач): флаг карточки `due_date_changed` истинен у любой задачи, срок которой когда-либо менялся, поэтому одной задачи от другой он не отличает; `updated_time` СТРОКИ СПИСКА сдвигается самим ответом (на 34 мс позже него); а `updated_time` ЗАДАЧИ в карточке меняется только когда меняют саму задачу (продлевают срок): у задач, получивших новый срок, он на 2,8 суток позже ответа Палаты, у остальных на месяцы раньше. Порядок решения: 1) дата продления в списке Excel («Муддат узайтириш санаси») в день ответа Палаты или позже → срок изменён, раньше → нет; 2) без неё: карточка говорит, что срок не менялся → нет; 3) задача в карточке изменена (или дата изменения срока) позже чем через минуту после ответа → да; 4) смена срока, замеченная синхронизацией после ответа, или (если время карточки не прочитано) изменение строки списка позже чем через 5 минут после ответа → да; 5) иначе задача остаётся в «Палата вернула». Время карточки скрипт присылает с версии 1.8.4: после обновления нужна одна синхронизация. В карточке задачи (администратору) под этапом написано «Проверка срока: …» со всеми датами, по которым принято решение. Кнопка «Диагностика» в скрипте спрашивает код задачи и выводит все поля-даты этой задачи (список, карточка, ответы) со значениями: только временные метки и флаги, без имён, телефонов и текстов. `updated_time` сайта это микросекунды от 1970 года, скрипт переводит их в миллисекунды.

**Сводная таблица в формате министерства (Excel).** На дашборде (администратор и специалист) выберите месяц и нажмите «Выгрузить в Excel»: файл `hisobot-ГГГГ-ММ.xlsx` повторяет форму сводной таблицы министерства, но только по нашему департаменту: заголовок «…ойига белгиланган… ТАҲЛИЛИ», дата и время «ҳолатига» (время последней синхронизации или загрузки базы), жёлтая строка «Департамент бўйича жами», зелёные строки управлений с их отделами, колонки ЖАМИ / Бажарилди (сони, фоиз) / Тизимда қолган топшириқ / Маълумот учун қабул қилинган (открытые задачи на этапе «Принято к сведению» Счётной палатой) и группы «Президент топшириқлари» (Фармон, Қарор, Баён), «Администрация раҳбари топшириқлари» (ПА), «Вазирлар Маҳкамаси қарорлари» (ВМ) с колонками ЖАМИ / Бажарилди / Қолдиқ; если есть другие виды документов, добавляется группа «Бошқа ҳужжатлар». Колонок риска («Юқори хавфли», «Ўрта хавфли», «Даврий», «Қизилга ўтган») в таблице нет. В файле есть и сами задачи (те же, что стоят за цифрами, того же периода): лист «Задачи по отделам» (управление → отдел → задачи, группы сворачиваются значком слева; в заголовке группы число задач, выполненных и нет), лист «Задачи по этапам» (этап согласования → управление → задачи; невыполненные по пути ответа, выполненные в конце) и лист «Все задачи» одним списком с фильтрами по отделу, этапу, статусу и месяцу. В строке: код, вид, документ, пункт, текст (до 400 знаков), ответственный, месяц срока, дата закрытия, официальный срок (только в файле администратора), статус, этап, отдел. Число строк на каждом листе равно «Департамент бўйича жами» на первом. Цифры те же, что на дашборде (месяц по сроку, который выбран в «Срок считать по»; «К сведению» не считаются). «Все месяцы» даёт таблицу по всем задачам.

**Почему у администратора и у других пользователей цифры за год или месяц могут различаться.** Официальный срок видит только администратор. Его дашборд по умолчанию считает месяц задачи по «дате закрытия, а если её нет, по официальному сроку», а у всех остальных месяц берётся только из даты закрытия: задача без неё не попадает ни в один месяц и год (она видна лишь при «Все годы»). Поэтому цифры за период у администратора могут быть больше на число задач без даты закрытия. Общее число задач при «Все годы» у всех одинаково. Переключатель «Срок считать по» у администратора имеет три значения: «дате закрытия, иначе официальному» (по умолчанию), «только дате закрытия» (точно как видят остальные) и «официальному сроку».

**Фильтры запоминаются.** Всё, что вы выставили на странице, остаётся, пока вы не измените это сами: период дашборда (год и месяц), вкладка, поиск по отделу, «Показывать отделы без задач», свёрнутые управления; все фильтры списка задач (отдел, сотрудник, статус, срок, вид, этап, даты, поиск, сортировка) и редактора. Вы уходите в другой раздел и возвращаетесь по меню, или обновляете страницу, и всё стоит как было. Запоминание идёт в этом браузере; открытая из числа дашборда ссылка (с её параметрами) сначала показывает именно эти фильтры, и они становятся новыми запомненными. Группа задач (Асосий / Ҳамижрочи / ВМ) и вид срока («Срок считать по») запоминались и раньше. Если запомненный период в этой группе пуст, показывается его год или все годы.

**Период дашборда.** В шапке дашборда выбираются год и месяц («Период»): плитки и все три таблицы показывают задачи со сроком в этом году или месяце (срок по «Срок считать по»), задачи без срока в период не входят. Цифры пересчитываются на месте, страница не перерисовывается; выбор сохраняется в адресе (кнопка «Назад» из списка возвращает на тот же период). Числа в плитках и таблицах открывают списки того же периода. В списке лет и месяцев показаны только те, где есть задачи. Тот же выбор определяет и сводную таблицу в Excel (год даёт таблицу за весь год: заголовок «… 2027 йилга белгиланган …»).

На дашборде под датой написано, когда данные обновлялись: «Обновлено: 23.11.2026 09:13 · синхронизация с ijro · база загружена 22.11.2026 18:40».

**Задачи по кодам и удаление (редактор).** В «Редакторе» задачи добавляются только по кодам: кнопка «Добавить по кодам», в окне список кодов (по одному в строке или через пробел). Платформа создаёт задачи с пометкой «по коду» и «ждёт данных с сайта»; при следующем нажатии «Синхронизировать» скрипт (1.8.0) скачивает списки сайта (останавливается, как только все нужные коды найдены), платформа находит в них эти коды и заполняет вид документа, документ, пункт, текст, срок, ответственного и его отдел, статус так же, как при импорте; остальное в файле не трогается. Коды, которых нет в списках сайта, остаются «ждущими» и перечислены в итоге синхронизации. Такие задачи не снимаются с дашборда загрузкой базы и входят в синхронизацию этапов. У каждой строки есть кнопка удаления (с подтверждением): задача удаляется с историей и этапами (задача, которая есть в файлах базы с сайта, вернётся при следующей загрузке этих файлов). Добавление и удаление доступны администратору и специалисту, записываются в журнал.

В списке задач первая колонка (код) теперь копирует код в буфер обмена, а не открывает сайт; ссылка на задачу на ijro осталась в карточке задачи.

**История ответов: только последний месяц.** Настройка «За какой срок читать и хранить ответы сайта» («Настройки» → «Синхронизация этапов»): по умолчанию 30 дней; можно 90 дней или всю историю. Скрипт передаёт только ответы за этот срок, платформа старые не хранит, этап считается по свежим ответам. Если на сайте есть ответы, но все старше срока, задача получает пометку «Нет ответов за последние 30 дн.» (этап по такому ответу не угадывается), на дашборде она в колонке «Другое», в карточке видно, сколько ответов старше. При смене срока уже сохранённая история скрывается сразу, без новой синхронизации.

**Периодические задачи: каждый период это своя задача.** В выгрузке сайта у периодической задачи по строке на каждый период (свой срок, свой статус). Задача в платформе теперь это «код + срок»: строки одного кода с разными сроками становятся отдельными задачами (код у всех один, как на сайте, срок и месяц свои), поэтому загрузка 2027 года не двигает декабрь 2026. Правила сопоставления строки файла: тот же код и тот же срок → та же задача; в колонке «Муддат узайтириш сони» стоит число (срок продлён) → у задачи этого кода меняется срок; у кода в файле несколько сроков, или у кода уже несколько задач, или такой срок есть в списке периодов, который прочитала синхронизация → новый период (внутренний код «КОД#срок»); одна строка с новым сроком без признаков периодичности → тот же срок ординарной задачи сдвинулся. Синхронизация читает код один раз, результат записывается всем периодам, а каждый период оценивается по своему сроку. Чтобы восстановить периоды, уже испорченные прежними загрузками, загрузите файлы всех месяцев (например, декабрь и 2027) вместе одним выбором в режиме «Добавить к существующим»: если в файлах у кода несколько сроков, периоды разойдутся сами.

**Документы Кабинета Министров: путь заканчивается Кабинетом.** Для задач из списка Кабинета министров (раздел «Вазирлар Маҳкамаси» на сайте: «Қарор (Янги)» и остальные виды) последний ответ «Снятие с контроля подтверждено (Nazoratdan olishni tasdiqlandi)» от Кабинета означает конец пути: платформа ставит статус «Выполнено» (этап «Назоратдан ечилди», в карточке «Снято с контроля Кабинетом Министров»). Для документов Президента и Администрации Президента этот же ответ остаётся шагом (дальше Счётная палата), статус не меняется. Правило применяется, только если этот ответ последний в истории (после него никто ничего не вернул), автоматически или предложением в «Синхронизация» → «Применить» (если автоматический режим выключен); статус, поставленный вручную, не меняется. Работает со следующей синхронизации.

**Три группы задач: Асосий ижрочи, Ҳамижрочи, ВМ топшириқлари.** Задачи разделены на три независимые группы, у каждой свой дашборд, свои списки и своя загрузка Excel; цифры одной группы не смешиваются с другой. Группа определяется строкой выгрузки: роль «Ҳамижрочи» (соисполнитель) → группа Ҳамижрочи; документ Кабинета министров любого вида, кроме «Қарор (Янги)», → группа ВМ топшириқлари (вид в таблицах остаётся таким, как на сайте); остальное, где министерство основной исполнитель (роль «Асосий»), → Асосий ижрочи (как было до сих пор). Переключатель из трёх кнопок есть в шапке дашборда, списка задач и редактора; выбор запоминается, ссылки из чисел дашборда открывают список той же группы, выгрузка в Excel тоже по выбранной группе (в заголовке файла название группы). **Импорт:** вверху страницы «Для какой группы эти файлы?» (по умолчанию группа открытого дашборда): загружаются только строки выбранной группы, строки двух других групп пропускаются (в предпросмотре видно сколько), поэтому загрузка одной группы никогда не меняет и не снимает задачи других (режим «Перезаписать» тоже относится только к выбранной группе). Один и тот же код может быть задачей и в Асосий, и в Ҳамижрочи: это две разные задачи. Задачи, добавленные по коду в «Редакторе», попадают в ту группу, к которой относится их строка в списке сайта. Синхронизация этапов по умолчанию читает задачи всех групп (настройка «Какие группы задач проверять синхронизацией»; ВМ топшириқлари ищутся в списке Кабинета министров); можно ограничить только Асосий. Прежний пункт «Отбрасывать соисполнителей и лишние виды документов» заменён выбором группы: строки другой группы в загрузку никогда не попадают. Все прежние задачи считаются группой Асосий ижрочи.

**Статус, поставленный вручную, с сайтом больше не сверяется.** Если человек поменял статус задачи (например, на «Бажарилган»: через карточку, редактор или массовое изменение; сотрудник, отметивший свою задачу выполненной, тоже), задача получает пометку «статус вручную»: скрипт не читает её с сайта (даже при настройке «читать историю и у выполненных»), синхронизация и «Применить» не меняют её статус и срок, в списке расхождений её нет, в карточке нет предупреждений «на сайте иначе». В карточке написано «Статус изменён вручную: с официальным сайтом эта задача больше не сверяется» и есть кнопка «Сверять снова» (администратор и специалист): после неё задача снова сверяется со следующей синхронизацией. Пометка снимается и загрузкой базы с перезаписью ваших правок. Статус, который платформа взяла с сайта сама (автоматически или кнопкой «Применить»), ручным выбором не считается. Это правило сильнее прежнего «Палата вернула открывает выполненную задачу»: вручную выполненную задачу Палата не откроет. В итоге синхронизации скрипт (1.8.5) пишет, сколько задач не сверялось из-за ручного статуса. У уже существующих задач пометка проставлена по истории: кто уже менял статус вручную, тот уже не сверяется.

**Перезаписать базу или добавить к существующим.** При каждой загрузке (страница «Импорт», шаг проверки) выбирается способ: «Перезаписать базу» (задачи, которых нет в загруженных файлах, снимаются с дашборда, в том числе выполненные: для полной выгрузки) или «Добавить к существующим» (задачи из файлов добавляются и обновляются, остальные не трогаются: для загрузки других месяцев поверх уже загруженных). Выбор по умолчанию берётся из «Настроек» («Задачи, которых нет в загруженной базе»); при смене выбора проверка пересчитывается, так что видно, сколько задач уйдёт с дашборда. Остальные правила (какие строки берутся, ручные правки) от способа не зависят.

**Скорость и несколько пользователей.** Скрипт читает задачи не по одной, а несколькими одновременно (настройка «Сколько задач читать одновременно», по умолчанию 3, от 1 до 5; при ошибках сайта скрипт сам замедляется). Если синхронизацию запустили сразу несколько человек, каждая задача читается кем-то одним: перед чтением порции из шести задач скрипт спрашивает у платформы (`/api/sync/claim`), какие из них свободны; занятые другим пользователем в последние 5 минут и прочитанные другим в последние 10 минут пропускаются (их результат уже в платформе). Тяжёлые операции платформы (загрузка Excel, приём этапов) выполняются в отдельных потоках и не задерживают запросы других пользователей. В итоговом сообщении скрипта показано, сколько статусов платформа обновила (выполнено / в работе).

**Если платформа временно не отвечает** (перезапуск сервера, сбой сети), скрипт сам повторяет запрос до трёх раз с паузой 3 и 10 секунд (повторяются только таймаут, обрыв связи и ответы 5xx/429; отказ 4xx, например неверный ключ, повторять бессмысленно). Уже прочитанные, но не отправленные ответы не теряются. Если и после этого платформа молчит, нажмите «Продолжить»: проверенное повторно не читается.

**Всё это настраивается** в «Настройки» → «Импорт и синхронизация», у каждого пункта написано, что он делает и какие есть варианты:
- *Загрузка базы:* ручные правки (перезаписывать / сохранять); задачи, которых нет в базе (снимать / оставлять); окно сроков (дней назад / вперёд, пусто = без ограничения).
- *Синхронизация этапов:* у каких задач читать историю: срок в текущем месяце (по умолчанию) / текущий месяц и просроченные прошлых / текущий и следующий / все невыполненные; какой срок решает месяц (дата закрытия или официальный); читать ли историю у выполненных (по умолчанию нет); автоприменение статуса.
- *Скачивание списков скриптом* (по умолчанию выключено, кнопка «Скачивать списки» в скрипте): если включить, скрипт сам приносит списки с сайта вместо ручной загрузки: три общих списка (по одному на раздел, со всеми статусами) или прежние 9 файлов, и список либо только обновляет статусы, либо ещё и добавляет задачи.

Предел размера файла при загрузке 40 МБ, до 10 файлов за раз.

## Перенос официального срока на другой месяц

Если официальный срок открытой задачи на сайте перенесли на другой месяц (было ноябрь, стало декабрь), задача раскладывается на две записи с одним кодом: запись **старого** месяца получает статус «выполнено» и закрепляется (сайт её не откроет заново), а запись **нового** месяца — копия с прежним статусом работы, прежним ответственным и текстом, без даты закрытия. В ноябре задача считается выполненной, в декабре — не выполненной, пока её не выполнят. Работает в двух местах: при импорте сырого Excel с сайта (там, где срок строки отличается от нашего по месяцу; сюда же относится «Муддат узайтириш сони» > 0) и при синхронизации (срок карточки между двумя проверками сменил месяц; периодические задачи сайта не затрагиваются). Не раскладываются: перенос внутри месяца (меняется только день), уже выполненные, снятые с дашборда и добавленные вручную задачи. В истории обеих записей есть строка «Перенос срока» (видна только администратору); в итоге импорта — «срок перенесён».

## Карточка задачи: этапы, история ответов, кто дал ответ (скрипт 1.4.0)

- **Один вид для всех задач:** вверху статус, ниже «Этап согласования» (Киритилди → Адлия вазирлиги → Вазирлар Маҳкамаси → Ҳисоб палатаси → Назоратдан ечилди), затем подсказка. У периодической задачи этап берётся из ответов **того периода, на который указывает наш срок**: ответы других периодов его не меняют; выполненный период показывается как «Назоратдан ечилди». Если скрипт ещё не передал период ответов (старая версия или задача не перечитана), карточка пишет «Этап периода уточняется» и не угадывает.
- **История ответов идёт от новых к старым.**
- **У каждого ответа указано, кто его дал** (Ҳисоб палатаси, Вазирлар Маҳкамаси, Адлия вазирлиги, исполнитель…): название органа, как на сайте. Имена людей не копируются; у секретных задач орган, как и текст, не передаётся.
- Орган и срок периода читает скрипт **1.4.0** (поля `org` и `pd` у каждого ответа). Чтобы карточки обновились, нужно обновить скрипт в Tampermonkey и запустить полную синхронизацию («Синхронизировать», не «Продолжить»): ответы перечитываются при каждой проверке задачи.

## Отделы департамента

Структура заложена из вашего списка: шесть управлений (I–VI), у I и III есть отделы. Она хранится в базе и **редактируется** в «Настройках → Структура департамента»: переименовать, добавить управление или отдел внутри управления, скрыть, удалить (удалить можно только пустой, иначе скрыть).
Сотрудник привязывается к отделу на странице «Пользователи» (при создании и в «Изменить»). Задача относится к отделу своего ответственного; задачи без ответственного и сотрудники без отдела попадают в строку «Без отдела», чтобы итог всегда сходился.

Дашборд (строгий деловой вид: плоские панели, тонкие линии, цифры одной ширины): сверху три плитки с полосой прогресса (всего задач, выполнено с процентом, не выполнено), ниже таблица по отделам с тремя вкладками. Строки: управления и их отделы (управление включает свои отделы; стрелка или кнопка «Свернуть управления» сворачивает их), «Без отдела» (задачи без ответственного или его отдела) и сверху «Весь департамент». Отделы без задач скрыты (галочка «Показывать отделы без задач»), отдел можно найти поиском.
- **По месяцам:** в ячейке процент выполненных и число задач («из N»), под ним полоса прогресса (зелёное — выполнено, красное — не выполнено) и две кнопки с числами, каждая открывает список; месяц берётся по сроку (дата закрытия или официальный, см. «Срок считать по»); столбцы «Без срока» и «Всего», текущий месяц подсвечен.
- **По видам документов:** то же по Фармон, Қарор, Баён, ВМ, ПА (и другим видам, если они есть).
- **По этапам согласования:** где невыполненные задачи: путь «Ответ не введён → Минюст → Кабинет Министров → Счётная палата», затем «Нужны действия» (Палата вернула, Возврат / запрос) и «Нет данных» (Другое, Не проверялись: этапы ещё не читали, какие задачи читает синхронизация, задаёт «Настройки»); число, доля от невыполненных отдела и полоса этой доли; в последней колонке — доля невыполненных среди всех задач отдела (полоса «не выполнено / выполнено»).

**Любое число и процент — кнопка:** она открывает список с теми же фильтрами (отдел, статус, месяц или «без срока», вид, этап), и в списке ровно столько задач, сколько было на кнопке. Выбранная вкладка хранится в адресе (`#/dashboard?view=stages`), поэтому «назад» из списка возвращает на ту же вкладку. Задачи «К сведению» в таблицы не входят. Что видит сотрудник, определяет настройка «Что видит пользователь»: при «Только свои задачи» список после клика содержит только его задачи.

## Специалист и редактор задач

Роль **«Специалист»** (назначается на странице «Пользователи») видит весь список задач и пользуется разделом **«Редактор»**: в строке меняет **срок исполнения** (дату закрытия), **ответственного** и **статус** (изменение сохраняется сразу, видно в истории задачи), а кнопкой «Новая задача» **добавляет задачу вручную** (текст, вид документа, документ, пункт, ответственный, срок исполнения). Официальный срок специалист не видит и не задаёт (его ставит только администратор), пользователей, импорт, синхронизацию и настройки он тоже не видит. Администратору редактор доступен так же.

Задача, добавленная вручную, получает свой код (`M00001`, …) и помечена «вручную»; **загрузка базы её не снимает** (её нет ни в каком файле) и синхронизация этапов её не читает. Помните, что загрузка базы перезаписывает статус и ответственного у задач из файла (настройка «Ваши ручные правки при загрузке базы»), а срок исполнения, которого нет в файле, не стирается.

## Вход

На странице входа можно открыть список сотрудников, выбрать себя (есть поиск) и ввести только пароль; страница запоминает выбор в браузере («Это не я» — выбрать другого). Обычный вход по логину остаётся («Войти по логину»), и это единственный путь для администраторов: их в списке нет.
В списке только те, кому выдан пароль (созданные импортом без пароля не показываются).

Что нужно знать: список **виден без входа**, то есть имена сотрудников может увидеть любой, кто откроет адрес сайта. Пароли и логины не раскрываются (в список уходят только id и имя, логин подставляет сервер). Если имена не должны быть видны посторонним, выключите список в «Настройках → Страница входа»; тогда остаётся вход по логину.

## Как считаются сроки

В выгрузке два срока. **Официальный срок** («Топшириқ муддати») — из поручения. **Дата закрытия** («Ёпиш муддати») — внутренняя, её ставит и меняет администратор.
Просрочка и группы сроков считаются по выбранному на странице: по умолчанию по дате закрытия (если её нет — по официальному сроку).
Переключатель «Срок считать по» есть на дашборде и в списке; его выбор запоминается.

Группы (только для задач «Не выполнено» и «В работе»): просрочено · срок ≤ 7 дней · 8–30 дней · позже 30 дней · без срока.
«Выполнено» и «К сведению» в просрочку не попадают. Процент выполнения = выполнено / (все − к сведению).

## Структура департамента: «Слить с…»

В «Настройках» → «Структура департамента» у отдела без вложенных отделов есть кнопка «Слить с…»: сотрудники этого отдела (а значит, и все их задачи на дашборде) переходят в выбранный отдел, название отдела из выгрузок сайта с этого момента относится к выбранному (следующая загрузка Excel кладёт задачи туда же), а сам отдел удаляется. Перед слиянием делается копия базы, действие записывается в журнал. Скрытый отдел-приёмник при слиянии снова становится видимым.

## Импорт

Страница «Импорт» (администратор). Сначала проверка без записи: сколько новых, обновится, без изменений, какие сотрудники будут созданы, что не удалось прочитать.
Затем «Загрузить».

**«Очистить базу»** (внизу страницы «Импорт», только администратор) стирает задачи — все или только выбранное: группа (Асосий / Ҳамижрочи / ВМ), год официального срока, тип документа, один документ; под выбором сразу видно, сколько задач будет стёрто (пустой выбор — вся база), а неизвестное значение выбора отклоняется, чтобы ошибка не расширила стирание. Стирается вместе с историей и этапами, в том числе добавленные вручную и снятые с дашборда; сотрудники, структура и настройки остаются. Нужно ввести слово `ОЧИСТИТЬ`, перед очисткой автоматически делается копия базы (имя копии показывается в сообщении), операция записывается в журнал. Нумерация ручных задач (M00001…) после полной очистки начинается заново. На дашборде число «не выполнено» в каждой ячейке по подсказке показывает, сколько из этих задач ещё в срок и сколько просрочено (по выбранной основе срока).

- Задача определяется по коду («Топшириқ коди»), поэтому повторная загрузка обновляет текст, документ и срок, а не дублирует.
- Всё, что администратор менял вручную (ответственный, статус, дата закрытия), повторной загрузкой не затирается.
- Сотрудники из колонки «Масъул ҳодим» создаются сами (роль «Пользователь», без пароля — войти нельзя, пока администратор не выдаст пароль на странице «Пользователи»).
- Нечитаемые даты (например, `16.17.2026`) не угадываются: поле остаётся пустым, строка попадает в список «Проверьте после загрузки». Опечатка `30.112026` понимается как 30.11.2026.
- Статусы из выгрузки: «Бажарилмаган» → Не выполнено, «Бажарилган» → Выполнено, «Маълумот учун қабул қилинган» → К сведению; пометки «Якунлаш», «Рақамлаштириш» сохраняются как метка.

Без браузера: `docker exec zadachi python -m app.cli import /data/файл.xlsx`.

## Напоминания в Telegram

Раздел «Напоминания» (виден всем). Бот присылает **одну сводку в день**: что просрочено и у чего скоро срок. Отдельные сообщения по каждой задаче не шлются, чтобы не превращаться в спам.
Дополнительно: сообщение сразу, когда администратор назначил задачу.

**Кнопки бота.** Под полем ввода постоянное меню: «📋 Мои задачи», «🔴 Просрочено», «📅 Эта неделя», «⚙️ Настройки», «❓ Помощь» (у администраторов ещё «📊 Сводка»). Под сообщениями — кнопки переключения (все / просрочено / неделя) и «🌐 Открыть на сайте» (появляется, только если в общих настройках указан адрес `https://…`: Telegram не принимает локальные и http-адреса в кнопках).
В «⚙️ Настройках» прямо в чате меняются личные правила: вкл/выкл, за сколько дней предупреждать, как часто о просроченных, уведомления о назначениях, «как у всех». Кнопки меняют только настройки самого человека, задачи из бота не правятся.
Команды те же: `/my`, `/overdue`, `/week`, `/settings`, `/stop`, `/start`, `/unlink`; они же в синей кнопке «Меню» у поля ввода.

Настройки на двух уровнях:
- **Администратор (общие):** включено/выключено для всех, время (Ташкент), дни недели, за сколько дней предупреждать (14, 7, 5, 3, 2, 1, в день срока), как часто повторять о просроченных (не напоминать / каждый день / через день / раз в 3 дня / раз в неделю), какой срок считать (дата закрытия или официальный), сводка для администраторов, сколько задач в одном сообщении, адрес сайта для ссылок.
- **Каждый пользователь (личные):** включить/выключить, свои дни предупреждения и частота по просроченным (или «как у всех»), уведомления о новых назначениях.
- Администратору доступны «Кому и что уйдёт» (проверка без отправки, с текстом сообщения) и «Отправить сейчас всем», а также журнал отправок.

Привязка: пользователь нажимает «Привязать Telegram», открывает ссылку и жмёт «Старт» в чате с ботом; страница сама замечает привязку. Код одноразовый и действует 15 минут.

**Подключение бота (один раз):**
1. В Telegram: **@BotFather** → `/newbot` → получите токен.
2. На сервере впишите его в `.env` проекта: `TELEGRAM_BOT_TOKEN=...` (только туда; не в чат, не в репозиторий).
3. `python3 manage.py deploy zadachi`.

Важно: нужен **отдельный бот** именно для этой платформы. Бот работает через `getUpdates`, а один токен не может опрашиваться двумя приложениями — если, например, использовать токен вашего бота-отчётов, оба начнут конфликтовать (в «Напоминаниях» администратор увидит ошибку конфликта).
Серверу нужен выход на `api.telegram.org`. Расписание и опрос бота работают в одном процессе из двух (блокировка в `/data/telegram.lock`), поэтому сообщения не дублируются.
Если человек заблокировал бота, привязка снимается сама. Одна сводка на человека в день гарантируется базой (уникальный индекс в журнале отправок).

## Дашборд обычного пользователя

По умолчанию (настройка «Дашборд пользователя» на странице «Настройки») обычному пользователю задачи раскладываются по месяцам и периодам так же, как администратору: по дате закрытия, а если её нет, по официальному сроку, поэтому цифры и месяцы совпадают. Точная дата официального срока ему по-прежнему не показывается нигде (ни в списках, ни в карточке, ни в выгрузке и напоминаниях); виден только месяц как столбец дашборда и фильтр по месяцам. Выключатель возвращает прежнее поведение: только даты закрытия, задачи без неё попадают в столбец «Без срока».

## Язык интерфейса: узбекский (кириллица) и русский

По умолчанию сайт открывается на узбекском (кириллица); в шапке и на странице входа есть переключатель «Рус / Ўзб», выбор запоминается в браузере (`localStorage.lang`) и меняется перезагрузкой страницы.

Программа написана по-русски; перевод делается в браузере: `app/static/i18n.js` переводит каждый текст, который попал на страницу (текст, `placeholder`, `title`, подсказки), по словарю `app/static/i18n-uz.js`: сначала целым текстом, затем фразами внутри, затем правилами для текстов с числами («5 задач» → «5 та топшириқ», «Показано 1–50 из 272» → «272 тадан 1–50 кўрсатилди», дни, сроки), затем отдельными словами. Данные (названия отделов, имена, тексты задач) в словаре не участвуют и не меняются; текст, которого нет в словаре, остаётся русским, ничего не ломается. Не переводится (`data-notr`): сам переключатель.

Добавили новый текст в интерфейс — добавьте его в словарь `i18n-uz.js` (русский ключ → узбекский перевод; для текстов с числами — правило в конце файла). Проверка: `node tests/i18n.test.js` (переводчик) и `BASE=http://localhost:8766 node tests/e2e/i18n.js` (обходит страницы и печатает тексты, оставшиеся русскими). Остальные браузерные тесты запускаются с русским языком.

Не переводятся: скрипт Tampermonkey на edo.ijro.uz, сообщения Telegram-бота и листы Excel-выгрузки (сводная таблица для министерства остаётся в принятой форме).

## Запуск

```
cp .env.example .env     # впишите APP_PASSWORD (не короче 8 символов)
docker compose up -d --build
```

Первый вход: логин `admin`, пароль из `APP_PASSWORD` (без него пароль генерируется и один раз печатается в `docker logs zadachi`).
База — `/data/zadachi.db` (том `./data`). Копии каждые 6 часов в `/data/backups`, хранятся 14 последних; страница «Настройки» показывает последнюю и проверяет её.
Копируйте `/data/backups` на другую машину: на том же диске они не спасут от потери сервера.

На общей платформе: запись проекта уже есть в `platform/projects.json` репозитория murojat; `python3 manage.py deploy zadachi`.

Для разработки: `pip install -r requirements.txt pytest httpx && pytest` (Telegram проверяется на поддельном API: `tests/fake_telegram.py`); `ZADACHI_TODAY=2026-11-16` фиксирует «сегодня».
Браузерная проверка: `BASE=http://localhost:8766 XLSX=файл.xlsx node tests/e2e/flow.js` (нужен Playwright).

## Устройство

FastAPI + SQLite (WAL), интерфейс на чистом JS без сборки (`app/static`), графики — SVG/CSS без библиотек.
Журнал изменений задач и журнал аудита защищены от правки и удаления триггерами БД.
Пароли — scrypt, заголовки безопасности и CSP, проверка Origin у запросов-записей, ограничение попыток входа.
Анимации отключаются при `prefers-reduced-motion`.

## Выгрузки «Hisobot» в синхронизации (скрипт 1.1.0)

> Это необязательный режим: с версии 1.6.0 скрипт по умолчанию **ничего не скачивает**, а только читает этапы (базу загружаете вы на странице «Импорт»). Если включить в скрипте «Скачивать списки», по умолчанию скачиваются три общих списка (по одному на раздел), а девять файлов ниже — режим «По разделам и вкладкам» в настройках. См. раздел выше.

Кнопка «Синхронизировать» в скрипте теперь сначала делает то же, что кнопка «Hisobot» на сайте, для трёх списков (президент, Администрация президента, Кабинет министров) и двух вкладок («Bajarilmoqda» и «Muddati o'tgan»): запрос отчёта, одноразовая ссылка (живёт около 5 секунд), скачивание xlsx. Файлы уходят в платформу (`POST /api/sync/export`) и импортируются как при ручной загрузке: только наши отделы, окно сроков −30/+60 дней, запомненное сопоставление отделов, строки соисполнителей пропускаются. После последнего файла предлагаются даты закрытия для новых задач. Затем идёт проверка статусов открытых задач, уже с учётом новых.
Статусы вкладок и типы документов хранятся на сервере (`GET /api/sync/export-plan`), поэтому правка не требует переустановки скрипта. Выполненные («Bajarilgan») тяжёлые: у президентского списка файл около 8 МБ и до минуты генерации на сайте, поэтому на этот запрос скрипт ждёт до 3 минут. Кнопка «Выгрузки: вкл/выкл» отключает этот шаг. Отделы, которые ещё не сопоставлены, скрипт только называет: сопоставить их надо один раз на экране ручного импорта.

Отбор по исполнителю: из выгрузки берутся только строки, где «Масъул ижрочи» — ровно **Соғлиқни сақлаш вазирлиги** (`site_import.EXECUTOR`; латиница и кириллица не различаются, более длинное название, например «… ҳузуридаги агентлик», не подходит). Остальные строки отбрасываются при любом импорте (ручном и из скрипта) и считаются на экране импорта («строк другого исполнителя»). Если в файле нет колонки «Масъул ижрочи», импорт отклоняется с понятным сообщением, а не пропускает все строки.

Из списка Кабинета министров берётся только вид документа «Вазирлар маҳкамаси қарори (Янги)»: скрипт запрашивает только его, а платформа при любом импорте (и ручном) отбрасывает строки остальных видов этого списка (список в `site_import.VM_NOT_KEPT`). Если на сайте появится новый вид документа Кабинета, его нужно добавить туда, иначе он будет взят.

## Только актуальные задачи с сайта (скрипт 1.2.0)

После полной синхронизации (все 6 файлов выгрузок получены и проверка статусов каждой открытой задачи прошла без сбоев и остановок) платформа ищет открытые задачи, которых нет среди «наших» строк выгрузок (наш отдел, не соисполнитель, нужный вид документа; срок значения не имеет) и которые проверка этого запуска нашла на сайте открытыми. Такие задачи получают статус «Нет на сайте» и пропадают с дашборда и из списков. Ничего не удаляется: история остаётся, задачу можно найти фильтром по этому статусу, а если она снова окажется в выгрузке, вернётся сама.
Не трогаются: выполненные на сайте (их нет в выгрузках по построению: качаются только открытые), задачи, не проверенные в этом запуске или не найденные на сайте, и задачи в состоянии, которое вкладки выгрузки не покрывают. Автоматически снимается не больше четверти открытых задач (минимум 10): если кандидатов больше, они ждут решения в разделе «Синхронизация» (кнопка «Убрать с дашборда»). Автоматическое снятие отключается там же.
